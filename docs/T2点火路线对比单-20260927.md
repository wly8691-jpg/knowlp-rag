# T2 点火路线对比单

> 工单《KnowLP 收口批》P1-4：**先单后码** —— 只出对比单，不动代码；实现另单。

## 一、必须带上的事实（实测，2026-09-27）

| 事实 | 数字 |
|---|---|
| trajectory 真实行 | **43**（9/11 → 9/27） |
| 其中 `consumed` / `rejected` **非零**的行 | **0** |
| `feedback_log` 的 `mcp-*` 口径 | **1 行**（9/19 16:55，全期唯一一次消费落账） |
| `preference_buffer.jsonl` | **0 字节**（偏好 pairs = 0） |

**根因不是"没人用"，是采集路径没覆盖真实行为**：自动捕获（`_auto_capture_consumed`）
只挂在 `knowlp_get_note` 上，而**读者（含采集端）日常直接读文件**，这个动作在 MCP 之外。

**第二重断点**：即便有消费记录，`preference_buffer.pair_edges()` **只处理显式
`chosen/rejected`**，`consumed/ignored` 被**降级为 fallback、不进 MLE**。

⇒ 所以 T2 现在是**双断点**：源头没数据（捕获）＋ 有了也喂不进（格式）。

## 二、三条路线

| 维度 | **A. 零摩擦捕获扩展** | **B. 消费单边 → 成对升级** | **C. 维持现状 + 人工纠正** |
|---|---|---|---|
| **做法** | 把「读了=消费」从 `get_note` 扩到读者实际路径；或约定采集端一律改走 `get_note` | `auto_feedback` 已同时产出 `consumed_edges` + `ignored_edges` —— 把这一对提升为成对信号（带权重/置信度）参与 MLE | 只吃人显式标的 `chosen/rejected` |
| **触发条件** | 读者读完一篇笔记 | 任何一次走 `auto_feedback` 的检索（读 A 不读 B 即一对） | 人主动标"哪个更好" |
| **数据质量** | 若靠约定 → 取决于习惯；若靠推断 → 噪声大 | **弱但真实**：读了≠有用；且**有位置偏差**（排前被读、排后被忽略） | **最高**（人明确的判断） |
| **改动面** | MCP 工具层 + **使用规范**（技术挂不上"读文件"） | `preference_buffer.py`（加单边→成对路径）+ 可能 `preference_mle` 的权重 | **零** |
| **风险** | **约定不一定被执行** —— 这正是当前失效的原因（约定走 `get_note`，人直接读文件） | **噪声放大**：弱信号反复强化会跑偏；不处理位置偏差会学成"排前的就是好的" | 样本量极低 → **偏好学习实质上不启动** |
| **本单能否立刻验证** | 不能（要改使用习惯后才有的观察） | **能**：历史上的 `consumed/ignored` 可离线重放 | 能，但样本=0 |

## 三、推荐

**以 B 为主，A 只做"可观测性最小版"；C 作为兜底口径保留。**

理由：

1. **A 单独不够。** "读文件"这个动作在 MCP 之外（宿主层的 Read），**技术上挂不上钩子**，
   只能靠"约定走 `get_note`"。而**同一个约定已经失效过一次**（全期仅 1 条落账）——
   把 T2 的生死押在一条执行不了的约定上，不是工程解法。
2. **B 有现成基础，代价最小。** `auto_feedback.py` **已经在产 `consumed_edges` +
   `ignored_edges` 两侧**，只是 `pair_edges` 不认这个字段名。把它接进成对路径，
   是**接线**而不是**造新机制**。
3. **但 B 必须先处理位置偏差**，否则学出来的不是"哪个更好"而是"哪个排在前面"。
   最小约束建议：**只把"检索前列却被忽略"当弱负样本**，排在末尾的忽略不计入。
4. **A 的可观测性最小版不是改代码，是加一个指标**：
   `走 get_note 的检索次数 / 全部检索次数`（**捕获率**）。
   现在连这个数都没有 —— 不先可观测，A 做没做成都无从判断。

**先做的一步（离线、零风险）**：用历史 `consumed/ignored` 做一次**离线重放**，
量化"单边→成对"能产出多少 pairs、位置偏差有多大。**有数了再决定 B 上不上。**
