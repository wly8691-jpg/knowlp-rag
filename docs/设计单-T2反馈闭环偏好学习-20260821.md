# 设计单 T2：反馈闭环偏好学习（先单后码）

> 状态：待 CC 按本单焊接 · 2026-08-21 · 对应交接单 T2（8/20-8/24）
> 论文参照：**《Efficient Preference-Based RL: Randomized Exploration Meets Experimental Design》**（NeurIPS 2025, EPFL SYCAMORE, arXiv:2506.09508）——清华×港大 DoF 评审 #005 解析，机制细节以论文 §3-4 为准
> decree 触发词：反馈闭环升级 / 偏好强化 / reward model

## 一、同构映射（先立尺子）

```
纠正记录（"A 比 B 相关"）  = 轨迹偏好对 (r ≻ r′)
图权重 θ                  = 奖励参数
四引擎扇出检索            = RL oracle（PAC 假设的落地替身）
```

核心目标：**用偏好学习替代手工规则调权重**——用户纠正记录进 buffer，攒批后学一次权重更新。

## 二、三个机制（抄思想，不搬实现）

### 1. 权重后验 + 随机化探索（RPO 核心）
- 论文：θ̂ ~ N(μ, Σ) 从奖励参数后验采样，在采样奖励下解 RL——比乐观探索便宜，比熵探索信息量高
- KnowLP：维护权重的不确定性（μ=当前权重，Σ=近似置信），**更新时从后验采样做探索**，不每条纠正立即全图重算
- 定位差：论文是连续参数空间 RL，我们是离散图权重——采样改在"候选权重向量"上做，用确定性规则近似即可

### 2. D-Optimal 主动查询（问最该问的）
- 论文：Greedy D-Optimal 选信息量最大的轨迹对去要标签，det(M + Σ ẽẽᵀ) 最大
- KnowLP：从候选集（低置信边 / 双引擎冲突边 / 用户纠过类似的边）中**主动选最不确定的边请求用户确认**——从"被动收纠正"升级为"主动问"
- 保守线：默认不主动打扰，仅当候选边置信低于阈值且攒够一批才触发一次确认请求

### 3. Lazy Update 攒批（支持多端收集）
- 论文：参数冻结期查询互相独立 → 可并发收集、批量更新
- KnowLP：纠正记录进 buffer，**信息量不足或未达批阈值不更新**；达阈值一次性 MLE 式更新 μ, Σ
- 由此获得：**多端收集纠正记录天然成立**——收集无状态可分发，更新单点归位

## 三、多端收集纠正记录（跨机结构）

```
收集端（无状态，可跨机）        更新端（单点归位）
├── 笔记本本机（主 agent）      └── 本机聚合：攒批 → 更新 μ, Σ → 回写图权重
├── 台式机分身（:8642）          
└── 手机/小智入口（后续）
```

- 收集端只产生"纠正事件"（对象 A、对象 B、方向、时间戳），**不直写存储**，上送更新端
- 更新端负责：事件校验 → 进 buffer → 攒批/阈值触发 → 权重更新 → 版本化记录（对齐 T5 版本化 rollout）
- 与双层记忆架构同构：重记忆留本机、分身只收集

## 四、Line2 接口预留
